# Concept 頁寫作原則

source 頁對來源負責：忠實、精確、可核對。concept 頁對讀者的理解負責：讀完要懂這個概念為什麼存在、怎麼運作、什麼時候失效。精確度由 source 頁承擔，concept 頁用句尾的連結繼承它。concept 頁是跨來源的整合，不是各來源摘要的合訂本。

## 理解的五個能力

讀者讀完 concept 頁，要做得到下面五件事。頁面的每一段都在支撐其中一項；不支撐任何一項的內容，移回 source 頁。

1. **必要性**：說得出它要解決什麼問題，以及最直接的做法為什麼不夠
2. **核心想法**：用一句話說出關鍵想法
3. **推導**：從核心想法推出機制，知道公式的每一項在回應問題的哪一部分
4. **預測**：從機制預測它在什麼情況下會失效
5. **定位**：知道前置、替代方案、後繼，以及什麼條件下選哪一種

## 結構

依問題組織，不依來源組織。標題用概念或設計軸命名，不用論文命名。

1. **定義與中心問題**：開頭一兩句定義，讓從其他頁連過來的讀者讀完就懂；下一句寫這一頁回答的中心問題（例如「LLM 的 RL 怎麼拿掉 critic，又能訓練穩定」）。接著列「前置知識」的連結。前置頁同時寫進 frontmatter 的頂層欄位 `requires`；第 6 步提到的替代或延伸關係也寫進頂層的 `alternative_to`、`extends`（不包在 `relations:` 底下，規則見 `SCHEMA.md` §3）
2. **問題**：目標是什麼、限制條件是什麼、最直接的做法是什麼，以及它為什麼不夠（必要性）
3. **核心想法**：一句話說出關鍵想法，再用白話說明它為什麼有效，附一個小示例（核心想法）
4. **機制**：核心公式與流程。公式的每一項各寫一句：它是什麼、在回應「問題」的哪一部分（推導）
5. **演進鏈**：從機制推出的失效，一個接一個被解決。每一步寫四句：前一步留下的問題 → 新想法 → 為什麼有效 → 它又留下什麼問題。順序依問題排，不依發表日期。同一步的多個變體可以用小表格：變體｜改了什麼｜出處。沒有線性演進的概念（例如 router 的各種設計）改依設計軸分小節，每一類仍寫這四句（預測）
6. **取捨與相鄰概念**：什麼條件下選哪一種；和相鄰概念的差別，連到它們的頁（定位）。跨來源的結論標「推論」
7. **仍有分歧的地方**：來源之間說法不同、或條件不同不能直接比較的地方；每一方只寫一句結論加出處

小頁可以合併段落，但定義、中心問題與核心想法一定要有。

## 解說與示例

來源常常只寫「怎麼做」和結果，不寫「為什麼有效」。整理者可以寫**解說**：用頁面已有的事實與公式，做白話說明或示例，不新增事實或數字主張。

- 解說段落開頭標「解說：」；示例標「示例（整理者構造）：」
- 示例的數字要能用頁面上的公式算出來，例如 4 個回覆得分 1、0、0、1 時，每個回覆的 group-relative advantage 是多少
- 解說不是推論：推論是跨來源的新論點，可以被證據支持或反駁；解說只是把頁面已有的內容講白

## 什麼留在 source 頁

concept 頁每個論點只寫一句結論，句尾附 source 頁連結，寫成「…（見 [Switch](../sources/x.md) p.7）」。下列內容留在 source 頁，concept 頁不寫：

- 單一來源的實驗設定、超參數、各家模型的訓練配方
- 「圖上目測」、整理者重算、原文筆誤、原文前後寫法不同
- 「待查證」的細節推理。concept 頁只留一句「X 待查證，見 [source 頁]」；這是下方「不要追加附註」的唯一例外
- 不影響取捨的數字。只有決定「該選哪一種」的數字才留下

## 新來源進來時

- **改寫論點，不追加條目**：先判斷新來源對既有內容的作用是哪一種：新增演進鏈的一步、修正某句話、提出反例、或替某句話加上條件。然後改寫那一句或那一段。不要在段落末端加一條以來源開頭的 bullet，也不要寫「補充（日期）」這類條目
- 新來源沒有改變任何論點時，只在 frontmatter `sources` 加上它，內文不改
- 一段裡引用超過一份來源時，不寫「同上」「上一節」這類相對參照，每次寫出來源名稱與頁碼或行號；指向別頁小節時寫出小節標題並用錨點連結。內文連到的 source 頁都要列進 frontmatter `sources`（lint 的 `sources_missing` 會檢查）

## 核對結果怎麼修

`source-verifier` 對 concept 頁判 ❌（漏條件、說得太廣），或 `concept-reader` 要求把單一來源的實驗細節（符號、基準、數字）寫進 concept 頁時，依序選第一個可行的修法：

1. 把句子改弱，例如加上「在數學題上」「作者認為」
2. 條件很複雜時，改成「條件見 [source 頁]」，條件寫在 source 頁
3. 刪掉這一句

不要在 concept 頁的句尾追加條件、頁碼與括號附註。

## 接住術語

source 頁把術語連到這一頁時，這一頁要有這個詞的定義（一兩句說明它是什麼）。沒有就在這次 ingest 補上，可以寫在開頭的定義段，或寫在相關小節的第一句。

## 讀懂檢查

ingest 改到 concept 頁後，派 `concept-reader`，派法見 `docs/dispatch.md`。依讀者回饋修改後，寫入前要再核對一次（同一份文件的 concept-reader 一節）：補白話與失效段時，最容易把推測寫成事實。
