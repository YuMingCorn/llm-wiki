# Source 頁寫作原則

模板見 `assets/source-page.md`，內容來自抽取單（`references/extraction.md`）。

## 通用原則

- **摘要不等於驗證**：論文的結果寫成作者的主張（「作者宣稱」「作者報告」），摘要本身不會讓主張成立
- **分開來源與解讀**：來源說的放「機制與方法」和「結論」；整理者自己的解讀、比較、白話簡化放「我的解讀」，標「推論」
- **定義要分範圍**：區分來源的定義和白話簡化；不同來源定義不同時，各自標明適用範圍，不合併成共識
- **絕不捏造**：引句、頁碼、數字都要來自實際讀到的原文
- **數字都要能定位**：內文的數字、表格與結論句都附頁碼或表號，不只「結論」
- **同一個數字只寫一次**：一個數字或結果在 source 頁只完整寫在一處（通常是「機制與方法」），一句話與其他段落用文字帶過，不再重複數字
- **「原文沒寫」只寫一次**：原文沒交代的事（訓練細節、資料前處理等）集中寫在「限制」，審閱註記、開放問題、研究脈絡不再重複列；開放問題只放這份來源引出、但真的沒解決的研究問題
- **附錄只寫有影響的部分**：附錄實驗只在支撐、修正或推翻正文結論時展開；其餘一行帶過：「附錄 X 測了 Y，結論 Z（p.N）」
- **讀者測試**：把頁面上所有實驗數字遮掉，「要解決的問題」「研究脈絡」和「機制與方法」仍要能回答 `PURPOSE.md` 核心問題 1 的四問：解決什麼問題、核心機制、和其他方法比的優缺點、在什麼條件下有效。答不出來就是脈絡不夠，數字再多也補不了。主對話寫完自己檢查一次，再由 `source-verifier` 的漏讀檢查驗收
- **主線寫成段落**：「要解決的問題」「研究脈絡」「機制與方法」「結論」照論證鏈的順序寫成段落，每段第一句承接上一段（例如「為了處理上面的通訊成本，作者…」）。公式、限制、審閱註記、檢查表、名詞維持條列或表格；研究脈絡的承先是清單（見下面「研究脈絡」）
- **圖上讀的數字要標明**：原文沒有寫出、從圖判讀的值，標「圖上目測，非原文數字」；原文表格是圖片時標「截圖判讀」

## 各段寫法

- **閱讀範圍**：寫明讀過的文字範圍，以及由主對話或閱讀 agent 閱讀。不逐一列出看過或沒看過的圖表
- **立場**：作者或機構有商業利益、未經同儕審查、或結果只是模擬時才寫，附頁碼；沒有就省略這行
- **一句話**：這份來源解決什麼問題、用什麼方法、主要結果，不超過 3 句
- **要解決的問題**：作者要解決的主要問題，以及作者說先前做法卡在哪裡，一段 2–4 句，每句附頁碼。照作者的說法寫，不加整理者的評價。這一節是全頁的主軸，「機制與方法」的每個小節都要能對回這裡
- **研究脈絡**：來自定位卡，分三段。**承先**：這份來源真正接續或沿用的前人工作，`**承先**：` 之後換行，每項一行，只用兩種寫法（這是「寫成段落」的例外，研究系譜工具靠它讀出箭頭）：
  - `- 接續 [A](…)：卡在 X（p.N）→ 本文改為 Y（p.N）`：只在作者自己說出 A 卡在哪裡時用，整理者不推測問題
  - `- 沿用 [A](…)：本文沿用它的 Z（p.N）`：直接拿 A 的元件或做法來用，或作者沒說 A 卡在哪裡
  - A 沒有 wiki 頁時寫名稱和年份，不加連結；都沒有就寫 `**承先**：無`
  - 不放進承先：只當比較對象的著作（寫進「機制與方法」或「結論」）、綜述列舉的方法、同系列的其他文件（寫進「這份改了什麼」或正文）

  **這份改了什麼**：一兩句，對照承先。**啟後**：只寫一句「見[研究系譜](../../meta/lineage/<主題>.md)」，每個所屬主題一個連結；完整的啟後由 `wiki.py lineage` 從其他頁的承先反推，不手寫。和 wiki 既有頁的矛盾、互補寫在啟後之後的段落
- **機制與方法**：解釋它怎麼運作，依論證鏈的順序組織小節。每個小節第一句寫這一步回應「要解決的問題」的哪一部分，再用段落寫做法與理由。公式與推導照原文轉錄，不刪。實驗數字只留支撐某個結論的 1–2 個，其餘寫「見原文 Table N」；不轉錄整張結果表，只摘錄支撐結論的列（超參數、方法比較這類小表照 `references/figures.md` 轉成表格）
- **結論**：放在「機制與方法」之後，讀者先看懂論證，再看作者得出什麼。一到兩段，回答「要解決的問題」；每個結論是能被反駁的具體說法，不是內容摘述，寫出成立的條件或樣本（資料集、期間、模型、設定）和證據位置（§、頁、表）。前面寫過的數字用文字帶過。不用表格：表格放在頁首會打斷論證順序。已經有「可驗證的主張」表的舊頁照留，不改寫
- **我的解讀**：沒有就寫「無」，不要硬湊
- **開放問題**：作者沒回答、或和 `PURPOSE.md` 核心問題相關但這份來源沒解決的問題；對未收錄論文的描述，註明全部轉述自本來源
- **名詞**：只解釋這份來源自己定義或用法和通用意思不同的詞，附頁碼；通用術語不在這裡解釋，連到 concept 頁。專有名詞一律寫英文，可附常見中文當搜尋別名（schema §4）
- **未讀章節**：只列兩種缺口：沒讀的章節，以及頁面結論依賴、但沒有親眼看過的圖表。其他沒判讀的圖表、參考文獻、不影響結論的附錄不列

## 方法與限制

- 每項寫明設計選擇，以及會扭曲結果的條件
- 每項標來源：「作者承認（附頁碼）」或「讀者推論」
- 說作者沒討論某件事時，要列出查過的章節
- 沒讀到的章節不下方法結論，缺口寫進「未讀章節」

### 審閱註記

檢驗作者的論證本身，放在「方法與限制」底下；「我的解讀」則是往外連結與延伸。開頭寫明這是整理者的判斷，不是原文主張。逐項看過，但只寫會改變結論或適用條件的發現；沒有就寫「無」，不硬湊。判斷標準：讀者知道這一條之後，對結論的信心或適用範圍會不會改變；不會就不寫。

- **措辭與資料相符嗎**：作者的形容（「about the same」「reliably」「significantly」）明顯比圖表或數字強或弱，而且會讓讀者高估或低估結論時，列出雙方與位置
- **結論依賴什麼假設**：模型輸入、樣本內估計值是否被當成未來參數；關鍵假設是否只寫在註腳
- **能重算的就重算**：原文給了公式與輸入時，挑結論最關鍵的一兩個案例重算。只有結果和原文有落差、而且落差會影響結論時才寫，寫明輸入、結果與差距；差距的原因沒有驗證就標「未驗證」。重算吻合、或只是四捨五入差異時不寫
- **原文疑似錯誤**：數字前後不一致而且會影響結論時才寫，附頁碼；要先確認兩邊講的是同一件事（同一批實驗、同一種算法），否則不算矛盾。不影響結論的筆誤、交叉引用錯誤、表頭標示錯誤都不寫

### 檢查表

檢查表依 `domain` 使用 `PURPOSE.md`「審閱檢查表」列的項目；`cross` 用它跨到的各領域的項目。每項都要看過，但表格只列「有發現」的項目並附依據；其餘項目在表格下寫一行「其餘項目看過，沒發現：…」。論文以外的來源只看適用的項目。讀法表「檢驗什麼」的其他項目（例如沒有消融支撐的設計、會隨版本過期的內容、授權）有發現時寫進「限制」或「審閱註記」，沒發現不寫。`PURPOSE.md` 沒列這個領域時，先請使用者補上。
