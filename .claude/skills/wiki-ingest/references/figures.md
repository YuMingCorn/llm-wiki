# 圖片規則

連結路徑規則見 schema §4（圖片用本機相對路徑）。

- source 頁放 3~5 張原文圖：優先方法／架構圖，其次是支撐核心論點的主結果圖；其他圖只在內文寫「見原文 Figure N」。沒有合適的圖就不放，在確認點說明原因
- concept 頁最多 1~3 張，只能引用 source 已有的圖：`wiki/assets/<source>/` 裡的截圖，或網頁來源自帶的 `raw/sources/<名稱>_images/`（不另外截圖、不複製）
- 不用 Mermaid 或其他自繪示意圖，避免和原文圖混淆
- 表格：小表（約 6 列、5 欄以內，例如超參數、方法比較）轉成 Markdown 表格；大型結果表截圖，或只摘錄關鍵列
- 每張圖下方一行斜體說明：原文編號與頁碼，加一句自然的說明句，說明這張圖顯示了什麼，需要時點出要對照的子圖。不用「看哪裡」這類指示語氣
  ```markdown
  ![Figure 2：模型架構](../../assets/2024-author-short-title/figure-2.png)
  *原文 Figure 2（p.5）。從 (a) 到 (b) 可以看出，模型先把輸入切成小段，再分別編碼。*
  ```
- 用截圖前要實際看過圖檔，確認裁切完整；`manifest.json` 標 `crop: page` 的是整頁截圖，需要時用 `pdf_tool.py shot --clip` 重截
